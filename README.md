# خادم منبّه الدواء (المرحلة 2)

يعمل **بمعزل عن الهاتف**: لذلك يكتشف عدم الرد حتى لو انطفأ هاتف المريض.

## ماذا يفعل
- يستقبل جدول الأدوية من تطبيق المريض، ويحسب هو مواعيد الجرعات بتوقيت المريض.
- إذا لم يضغط المريض «أخذته» بعد 10 دقائق ← رسالة للمرافقين، بعد 20 دقيقة ← رسالة عاجلة، ثم كل 10 دقائق (6 مرات). عند الرد ← «استجاب الآن».
- يستقبل «نبضة» من الهاتف كل 5 دقائق (مع نسبة البطارية). إذا انقطعت أكثر من 20 دقيقة وكانت هناك جرعة خلال ساعتين أو جرعة بلا رد ← «الهاتف غير متصل، قد يكون مغلقاً أو نفدت بطاريته». وعند عودته رسالة «عاد للاتصال».
- الربط: المريض ينشئ رمز دعوة (8 خانات، 24 ساعة، يُستعمل مرة واحدة) ويدخله المرافق. كل مرافق يحصل على Topic سري خاص به، والإشعارات تصل عبر تطبيق ntfy.
- لغة الرسائل (عربي/ألماني/إنجليزي) يختارها كل مرافق.
- صندوق إرسال (outbox) يعيد المحاولة تلقائياً إذا فشل الإرسال.

## التشغيل
1. استأجر VPS صغيراً (أو استخدم حاسوباً دائم التشغيل)، ووجّه دومين إليه.
2. `DOMAIN=example.com docker compose up -d --build` (يشغّل HTTPS تلقائياً؛ التطبيق **يرفض** http).
3. من دون Docker: `python3 server.py` (يحتاج Python 3.9+ فقط).
4. اختبار: `python3 test_server.py` (يجب أن يطبع ALL PASSED).
5. انسخ مجلد `data/` احتياطياً بانتظام.

متغيرات: `PORT`, `DB_PATH`, `NTFY_SERVER` (خادم ntfy خاص موصى به), `NTFY_TOKEN`, `TICK_SECONDS`, `TRUST_PROXY=1`.

## الخصوصية والأمان
- لا تُرسل أسماء الأدوية إلى الخادم إلا إذا فعّل المريض «مشاركة أسماء الأدوية».
- الرموز مخزّنة مُجزّأة (SHA-256)، ومحاولات الانضمام محدودة (10 في الساعة لكل عنوان).
- لا يوجد تشفير طرف-إلى-طرف: صاحب الخادم يرى الجدول (بلا أسماء افتراضياً) وأوقات الرد. لا تشغّله لغيرك قبل مراجعة قانونية لحماية البيانات الصحية (GDPR إذا كان مستخدمون في أوروبا).
- ntfy.sh العام: من يعرف الـTopic يقرأ الرسائل. الأفضل خادم ntfy خاص.
